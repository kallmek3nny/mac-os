  Two things that looked green and weren't

  The resume initially fetched with os_type='default' and Apple served a real,
  correctly-signed 884,317,790-byte image — byte-identical in size to the Sonoma
  recovery already on this disk. The board ID was right the whole time; Tahoe's
  table row carries "os_type": "latest", and that field selects which image the
  same board ID resolves to. Appending would have produced a file of exactly
  the right length containing two different macOS builds spliced mid-stream.

  EFI/OC/Resources tree containing four empty directories and zero files —
  OpenCore's release package ships no picker icons or fonts, they live in a
  separate OcBinaryData repo. ocvalidate reads the plist and never looks at the
  filesystem beside it. Switched to the Builtin text picker, which needs no
  resources.
