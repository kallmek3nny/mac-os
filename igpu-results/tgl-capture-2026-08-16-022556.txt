THE SCRIPT'S OWN VERDICT WORD IS WRONG ON THIS PLATFORM
------------------------------------------------------
igpu-plane-dsi.sh's dead() treats None and 0xFFFFFFFF as unreadable, so
any page reading 0x00000000 came out as "ABSENT". On this silicon EVERY
unused display page reads 0x00000000, not all-ones. Transcoders B, C and
D certainly EXIST on Tiger Lake, so "ABSENT" is false for them; the true
state is DECODED-BUT-UNPROGRAMMED. Read every ABSENT above as
UNPROGRAMMED. The dry-run harness could not catch this because its
synthetic BAR was filled with 0xFF, which is what the author expected
hardware to do and not what this hardware does.

Q1/Q2 -- NOT SETTLED, and the probe was incapable of settling it
---------------------------------------------------------------
DSI0 (0x6B000), DSI1 (0x6B800) and the stride probe at 0x6C000 all read
0x00000000. Zero is what an unprogrammed page reads here, so 0x6C000
being zero does not distinguish "DPCLKA lives here" from "a timing block
lives here". The 0x800 DSI stride in IntelDisplay.hpp remains sourced to
reference/i915/intel_display_device.c:79-80 and UNWITNESSED. An eDP-only
laptop cannot answer it: nothing will ever program a DSI transcoder here.

Q3 -- plane count NOT settled, for the same reason
--------------------------------------------------
All 7 probed slots on all 6 pipes returned a readable 0x00000000. A
disabled plane and a non-existent slot are therefore indistinguishable,
so "7 readable slots" bounds nothing. The only positive fact is that
plane 1 of pipe A is live at 0x70180 and plane 2's slot at 0x70280 is a
distinct address, which is consistent with the 0x100 stride but does not
prove a count.

PIPESRC's +1 matches eDP-1's advertised 1920x1080 exactly. This is the

FIELD ORDER IS INVERTED BETWEEN PIPESRC AND PLANE_SIZE:
  PIPESRC    0x077F0437 -> width  in 31:16, height in 15:0
  PLANE_SIZE 0x0437077F -> height in 31:16, width  in 15:0
Both encode 1920x1080 minus one. The two words are byte-swapped halves of
each other, which is exactly the kind of pair that produces a silently
valid wrong answer if one decoder is reused for both.

PLANE_SURF (+0x1C) and PLANE_SURFLIVE (+0x2C) both read 0x01058000 -- a
real 4 KiB-aligned GGTT offset, and their agreement is evidence both
addresses are right rather than one being an alias.

PLANE_CTL 0x82009000 decodes as: bit31 ENABLE=1, bits 27:23 format=4
(XRGB8888), bits 12:10 tiling=4 (PLANE_CTL_TILED_Y). Bit 15 is set and
is NOT decoded here on purpose -- naming it would mean inventing a name.

PLANE_STRIDE 0x3C = 60. The panel is 1920 px at 4 B/px = 7680 B/line,
and 7680 / 60 = 128, so the stride unit on this Y-tiled surface is 128
bytes. Derived from ONE sample; it is not a witnessed unit field.
